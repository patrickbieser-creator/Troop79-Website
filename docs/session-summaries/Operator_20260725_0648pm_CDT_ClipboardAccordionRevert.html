What Happened

Reported by a real user: Patrick relayed that a scout's desktop Clipboard view was blank for every rank except her current one — a direct regression from the mobile accordion shipped earlier the same day.

The earlier session's mobile-optimization work added a per-rank collapsible accordion to the Scout Clipboard, built on native HTML <details>/<summary> elements with CSS intended to force all ranks open on desktop and in print, regardless of the collapsed state. Two rounds of CSS were tried, in production, before the real root cause was found:

AttemptFix TriedResult
1 display: block !important Failed — still blank on desktop
2 Added content-visibility: visible !important Failed — still blank, confirmed via a fresh deploy and hard-reload
3 Full revert to a plain, always-rendered <div> Fixed — verified across all 7 ranks via direct DOM query

Root Cause

A closed <details> element's non-summary content is hidden by Chrome as browser-internal "skipped content" — not an ordinary, cascade-overridable display or content-visibility value. No CSS specificity or !important can force it back into the render tree. This was proven, not guessed: getComputedStyle reported the content as fully visible and block-level, while elementFromPoint/innerText showed the browser's actual layout and hit-test engine still treated it as absent.

Why the pattern seemed proven before this: the accordion design was modeled on an existing "Merit Badges In Progress" trick that forces its own <details> sections open specifically for @media print. That trick only ever worked because Chrome's print rendering pipeline doesn't apply the same content-skipping behavior in the first place — it was never actually evidence the technique would generalize to the interactive screen case.

Fix

Reverted RankBlock to a plain, always-rendered <div> — the exact pre-accordion structure. Kept everything from the original mobile-optimization work that was correct and unrelated to the accordion: the larger mobile font sizes, text wrapping instead of tooltip-only truncation, and the dead 230px alignment-gap fix.

Cost

The mobile Clipboard is back to one long scrollable column instead of a collapsible accordion — the original "1400px+ of scroll" concern is unresolved again and back on the Backlog. That was always the lower-priority half of the original ask; the critical fix (text actually readable on a phone) is untouched.

Process Lesson

Both prior verification passes checked only 1-2 of the 7 rank blocks via a partial screenshot rather than scrolling through the entire section or querying the DOM directly — that gap is exactly why this shipped broken twice before a real user caught it. This revert was verified against all 7 ranks via direct DOM inspection (elementFromPoint, row counts per rank) before being called done.

Decision

  • D-070 — Reverted the Clipboard mobile accordion. Established that <details> closed-content hiding is not CSS-overridable outside @media print; any future collapsible section needs a different mechanism entirely (checkbox-hack CSS accordion, or client-side JS) — not this pattern. Supersedes the accordion portion of D-069; that decision's font-size/wrap/gap findings remain valid and shipped.

Next Steps

  • Mobile Clipboard scroll-length is back on the Backlog, unsolved — needs a genuinely different collapse mechanism if revisited
  • No other action needed — production is confirmed correct for all 7 ranks on both mobile and desktop
