What Was Accomplished

Resource Library Phase 2 (v1.21.0): proof-of-completion goes live

A scout or family can now submit a photo, link, or write-up as proof of a completed requirement — new /library/submit-proof, "I did this" call-to-action buttons on rank and merit badge requirement pages, and an admin Proof Queue tab that approves through the exact same duplicate-blocked ledger path Fast Entry already uses (extracted to a shared lib/ledger-dedup.ts helper). Approval self-heals a two-leaders-approve-at-once race rather than double-writing the ledger. First private Supabase Storage bucket in the project — no public access, signed URLs generated server-side only. qa-lead review came back clear; two real bugs were caught and fixed along the way (a foreign-key delete-order issue in the test suite's own cleanup, and the concurrent-approval race itself). Shipped alongside a site-wide Log Out utility that clears all three session types (family, household-binding, admin) from one button.

Hours after v1.21.0 shipped, a real gap surfaced in it: the scout-login path into /library/submit-proof used a roster picker with no identity check behind it — any holder of the shared scout password could submit proof under any active scout's name. Not a malicious-actor risk so much as a plain misclick: thirty names in a dropdown, no confirmation step, feeding straight into an admin approval that writes to the ledger.

Phase 0 (v1.21.1): closed the same day it opened

Refused the scout-login path outright, server-side — the same way a leader session already was. Not narrowed, not confirmation-gated: closed. scout-roster-picker.tsx was deleted rather than left disabled, and the "I did this" buttons now explain what to do instead (submit from a family device, or ask a parent) instead of letting a scout fill out the whole form only to be refused at the end. This was also the opening move of a much larger plan drafted the same day: Plans/Family-Identity-Auth.md — passwordless per-family identity to replace the self-asserted household picker everywhere it's load-bearing. qa-lead: clear, ship, no critical or high findings.

Family Identity & Passwordless Auth, Phases 0–2 (v1.22.0): the real fix

New /signin: enter an email, get a one-time link and a 6-digit code, land in a 120-day session bound to a real person and household. No password to remember, and no more self-asserted "pick your own household" picker standing in for identity. Enumeration-safe (identical response whether or not the address is on the roster), rate-limited, and the emailed link's landing page consumes nothing on a bare GET — so a mail scanner prefetching the link can't burn the token before the real recipient clicks it. Verification tokens are stored as salted SHA-256 hashes only.

Three surfaces now trust this instead of a picker: /profile requires a verified adult (the old household picker is deleted, not orphaned); Resource Library proof submission gets its scout path back — properly this time, a verified scout can submit proof of their own work again, with no picker and no way to claim anyone else's; Event Signup recognizes a verified visitor automatically, skipping the password re-prompt and pre-selecting their household (still switchable — locking a family to only their own household was explicitly rejected as a capability regression, since a grandparent or family friend legitimately signs up on someone else's behalf).

Revocation runs off a per-person session counter that the database itself bumps whenever the roster marks someone inactive — catching bulk import corrections and direct database edits, not just app-side changes.

qa-lead's two passes earned their keep here. The first caught per-IP rate limiting that looked implemented but was silently dead code — the IP address was never actually threaded through to the check — and a revoked session that kept full Event Signup write access indefinitely, because the access-check function had never been taught to look at the new revocation counter. Also fixed: a smaller enumeration side-channel hiding in the code-entry lockout message. The second pass: ship, no blockers.
