What Was Accomplished

Event Signup UX wave (v1.24.0–v1.27.0)

  • Jobs panel rebuilt for 30–40-job bulk entry: titled “Add a job” card above the list (it was a bare row of inputs below it, drifting off-screen with every add), Enter-to-add with focus return, panel-local errors, a Duplicate action, delete confirmation on unclaimed jobs, and chronological family-facing ordering with an id tiebreaker — ties previously had undefined order.
  • Per-job descriptions replaced the single signup-wide intro line; per-claim comments (“I have a 6ft table”) flow to the leader roster and CSV without disturbing the coverage tally.
  • Adults without a scout can finally volunteer — the job board's picker only searched scouts; committee members and counselors (exactly who works a fundraiser) were told “no scout by that name.”
  • Signed-in leaders stopped being second-class: the household prefill now runs for any session that identifies a person. The rummage sale's jobs were then entered for real on production, and the Resource Library superuser proxy (D-078) was granted and verified live — that feature is now fully closed.

The meeting-date bug, which was three bugs (v1.27.1 + follow-ups)

  • Publish discarded unsaved logistics — the header button only flipped status; the date lived in a form saved by a different button. Publish now commits the form first.
  • The new-meeting date field looked like a filter — it sat unlabeled between year/status filters, so every meeting silently got the default next Sunday. It now lives in a labeled create row that opens on the first free Sunday.
  • Typed dates were reverted on click-away in the shared date picker (outside-click closed the popover before blur committed the text) — fixed for every admin date field at once.

Event→News merge — the OMG consolidation, ported (v1.28.0)

  • Read the OMG-Website implementation (their D-011: “merge at the feed, not the tables”) and applied it here, where the duplication was worse — three overlapping event representations, and a homepage “Upcoming Events” box that only knew about events someone had hand-written a duplicate article for.
  • Calendar entries now promote themselves into the news feed (window, card summary, hero image, optional homepage-hero turn); cards link to the event page with the live signup. Create either a news item or an event — never both.
  • The legacy machinery (article_id, article event columns, the “event” article type) was dropped via a two-phase migration with a guard against destroying live event data; the duplicate Rummage Sale article was archived on production with the calendar keeping full coverage.

News & Events section + content taxonomy (v1.29.0–v1.30.0)

  • New public News & Events page in the main nav: chronological grid of posts + promoted events, tag chips, pagination, and a public archive view. Admin renamed Articles→News; the pointless Type dropdown removed; a leader-guarded “Feature on homepage” checkbox added to the editor.
  • on_calendar flag: external opportunities (district merit badge clinics, outside service days) are events that keep their page and news promotion — and self-expire — without ever touching the troop calendar. Admin screen renamed Calendar→Events: it holds every event; the calendar is one view.
The settled taxonomy: dated-and-ours → calendar event · dated-but-external → off-calendar event · no date at all → news post (with auto-archive for time-limited relevance) · weekly meetings → the Meetings system. One honest question at entry time instead of a content-type puzzle.
