What Was Accomplished

Calendar categories became data (v1.31.0)

  • The taxonomy left the codebase. Categories had lived in three places at once — a CHECK constraint on calendar_entries, a second copy on photo_albums, and a TypeScript union — and that duplication had already drifted once, breaking album creation in July until the two constraints were hand-resynced. They are now rows in calendar_categories, editable under Lookups & Admin with a color picker.
  • Renaming is now a one-field edit. Both tables reference the label by foreign key with cascade-on-update, so a rename rewrites every event and every photo album in one statement. A category still in use cannot be deleted — the site says what is using it rather than failing quietly.
  • The rename trap was designed out. Three places in the code compared a category by name (the Meetings system, the Event Signups screen, the meeting placeholder). Renaming “No Meeting” would have silently broken all three. A behavior flag now carries that meaning instead, so labels are free to change.
  • Seeded from the existing 14 categories with their exact printed-legend colors, so nothing shifted visually — including in the Bugle.

The date picker stopped covering the form it belongs to (v1.31.0)

  • Opening an event for editing sprang the calendar open on top of the form. A modal focuses its first field automatically, that field is a date, and the picker opened on focus. It now opens on a deliberate click (or the down-arrow key) — which also stops a calendar appearing every time you Tab past a date field.
  • Fixed in the shared component rather than the one screen, so the ledger’s row-edit box — which opens onto a date field too — was fixed in the same change.

The Resource Library got a front door (v1.32.0)

  • The library could not be stocked from the admin at all. Every resource row came from the family-facing suggestion form or a one-purpose import script, so adding one meant submitting a link as if you were a family and then approving your own submission — and three of the five kinds had no way in whatsoever.
  • All five kinds are now enterable: link and video by URL, image from the media library, document by uploading a PDF or pasting a link, and a troop post written in markdown with a live preview beside it. Where a resource appears — any number of shelves, rank requirements, or badges — is chosen while you enter it, so it lands on its pages in one pass.
  • Anything entered in admin publishes on save. The review queue keeps doing what it was built for, which is reviewing what families and scouts send in. “Save as draft” parks an unfinished one.
  • “Leaders only” started working. The setting had existed in the database since the library shipped, but no page ever checked it — a leaders-only resource would have rendered for every family. It is now enforced everywhere, including in one query that bypassed the shared loader and would have leaked on its own.

Blockers Resolved

Production was quietly degraded, and nothing said so. The categories migration reached production after its code did — the earlier commits were pushed from a concurrent session. Because the loader discards its error object, a missing table became an empty list instead of a failure: the calendar’s category filter was empty, every category rendered in the neutral grey fallback, and the admin category picker had no options, which blocked adding events and albums. Diagnosed from the live page’s HTML, migration applied, and recovery verified — 15 filter options and real colors back.
Then the page stayed stale anyway. /events was prerendered fully static with no revalidate window, so its HTML was whatever the last build produced — and it survived the next deploy untouched. It now carries a 30-minute floor, matching Photos and Meetings. On-demand refresh from admin actions is still the fast path; the window is the backstop for data that changes outside the app, which a migration does.

  • Create the new off-calendar categories — “Merit Badge Opportunity” and “Service Opportunity” — in Lookups & Admin. That was the point of the whole lookup: they are yours to word.
