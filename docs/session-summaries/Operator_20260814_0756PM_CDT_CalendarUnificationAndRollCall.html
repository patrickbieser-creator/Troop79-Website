The finding that matters most to families: the check behind Second Class 1a and First Class 1a was counting only campouts and hikes, so every fundraiser, day outing and service project a scout attended was invisible to it. Four active scouts had already met a requirement and were not being credited. Two of them — Oscar Belle and Henry Ellerman — had the required campouts all along and were held back purely by service days and fundraisers that did not count.

What Was Accomplished

The calendar unification (v1.33.0)

Three admin screens described the same act — “something happens on a date.” Committee members entering content experienced them as three front doors to one job, and they were right. meetings was a parallel system keyed by meeting_date UNIQUE with no foreign key to the calendar, correlated only by a matching date string resolved at read time. Editing either side’s date split the pair silently, and a meeting entered on the Meetings screen never reached the calendar page, the homepage sidebar or the .ics feed — Outlook and Band never saw it.

Meetings became a layer on calendar entries via a real foreign key rather than being absorbed into them, so meetings.id survived and 1,249 historical check-ins needed no surgery. Several meetings may now share a date, which is what forced /events/[id] to become the single public permalink. The standalone /meetings section was deleted outright.

ICS correctness came free. After the merge, a meeting that is not on the calendar cannot exist. The feed route’s code did not change at all.

Cloning became the primary way events are created (v1.34.0)

Patrick retired the premise behind the old quick-entry dialog: bulk entry is over, roughly 99% of entries are one-at-a-time, and almost all of them want thought — so the fastest route to a thoughtful entry is last time’s entry. Clone now carries every layer (write-up, agenda shape, signup structure) and never carries people. Date-relative fields shift, so a three-day campout stays three days and a deadline ten days before stays ten days before. Copies start unreviewed: signup closed, agenda draft.

Verified live: a campout clone preserved its Oct 9–11 span as Nov 13–15, and a Troop Meeting clone carried all six agenda sessions with titles, times and tracks intact while clearing every leader name and scout list.

Roll Call, for every event (v1.37.0)

Attendance had only ever existed for meetings. Campouts, service projects and fundraisers had attendance too, but it was entered later as advancement credit and no screen showed who was actually there. Roll Call now opens on any event, seeded from the signup where one exists, correctable by hand for the RSVPs that arrive by email or in conversation.

The architectural decision was not to move advancement quantities out of the ledger. Measured first: the ledger is read by 32 code files, 24 migrations, 4 views and 3 triggers including the one that awards ranks — whose failure mode is silent and slow. Roll Call writes ledger rows instead, so nothing that reads them changed.

Blockers Resolved

ProblemDiagnosis
Roll call taken for “Summer Camp at Tesomas” still showed not taken The 26 attendees were saved; the list read the table unpaginated and PostgREST caps that at 1,000 rows silently. Production held 1,316, and that event’s rows fell in the dropped 316. Same landmine as D-028.
Reconciliation audit crashed on load ledger_active is a view defined as select *, which Postgres expands at creation — so a newly added column was invisible through it until the view was recreated.
News hero image cropped to a strip A forced 16:7.2 aspect ratio with object-fit: cover. The rummage poster is 1103×1426 and was rendering 980×441 — roughly two thirds discarded.
Markdown lists had no bullets Tailwind v4’s preflight resets ul, ol { list-style: none }, and the article stylesheet set list padding without ever restoring the marker.

Quality Gates

qa-lead ran twice and earned its keep both times. On the calendar unification: ship-with-fixes, no critical findings, security clear. On Roll Call: two CRITICAL.

1. Credit could silently duplicate. syncCredit looked for an existing row with .maybeSingle() and discarded the error — so when two rows shared a pair, PostgREST returned an error with null data, the code read “no row exists” and inserted a third, compounding on every re-save. Fixed with a database unique index and an upsert against it.

2. Two writers into one ledger slot. The old meetings attendance screen wrote rows Roll Call could not see, so the first Roll Call of a meeting somebody was already checked into would create a duplicate — the default outcome of using a page nothing warned leaders off. The second writer was removed rather than coordinated with.

The lesson taken: bug 1 sailed past a green 171-test suite because the cascade lived inside a server action nothing could invoke. The codebase already had the answer — an existing lib module exists for exactly that reason — and it was not followed. The cascade now lives in a testable module with eight direct tests, including the duplication case.

Deployment Discipline
