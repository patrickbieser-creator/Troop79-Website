The finding that matters most: outbound email had never sent a single message. The Resend key in .env.local was the pre-rotation one and EMAIL_FROM was never set, so every send since the integration shipped had silently reported skipped. Nobody noticed because "unconfigured is a no-op" is by design. The first real message from the troop's account was sent this session, after building a relay so testing cannot reach a family.

What Was Accomplished

Families can now maintain their own household

/profile covered scouts only, so a parent could correct their child’s address but had no way to fix their own phone number — and there was no front door anywhere for adding an adult to the troop. A committee member or merit badge counselor with no scout could only arrive through a spreadsheet import or by being attached to an event signup.

  • Every household member is now listed — scouts and adults — one selected at a time, replacing a stack of per-scout accordions.
  • Adult edits queue for the same leader review scouts already get, riding change_requests’ generic (entity_type, entity_id) key. No migration was needed.
  • Families can add a household member, which writes immediately and links to an existing person on a known email rather than duplicating.
  • Birthdate is family-editable (the troop needs it for adults on campouts); BSA member ID deliberately is not — that number comes from Scouting America and feeds the Scoutbook export.
Caught during testing: adding a member writes immediately, so unlike an edit there was no pending row and the only trace was an email — a family could put someone on the roster unnoticed. New members now raise a dashboard notice. It is deliberately a notice, not a proposal: it has an empty field allowlist and no apply target, so acknowledging it cannot write to any record, and it offers no “Reject” — that would read as “remove this person” on someone who already exists.

Three markdown editors became one

D‑088 had recorded the debt precisely: “two markdown editors now exist; extract if the library one grows, don’t add a third.” The calendar workbench had become that third consumer. Finishing the extraction hit a shape problem — the article editor’s preview is a full-height column of the page, so folding it into one composed pane would have squeezed both halves into the left column.

  • The component now exports its halves separately, so the article editor keeps its page shell while sharing one textarea, one preview and one cheat sheet.
  • The insert machinery — five toolbar buttons, gallery-link and video prompts, cursor math, click-to-edit on an existing block — moved into a shared hook.
  • The article editor shed roughly 350 lines; the library post editor and the event story panel gained the whole toolset.
  • D‑081 is finally true rather than approximately true: event stories now get the news editor’s experience it promised, not a textarea with a preview beside it.

Every native date input retired

Six places still used the browser’s built-in date box, which looks and behaves differently on every device. All six moved to the shared picker, which needed two new adapters: one for the plain method="get" report forms, and one for the single field that needs a moment rather than a day.

That last one uncovered a real bug. The signup deadline was seeded with the first 16 characters of a timestamptz — which Postgres returns in UTC — but rendered as local time. A 6:00 PM deadline displayed as 11:00 PM, and shifted another six hours every time the field was touched.

Email works, and testing it cannot reach a family

The existing rules kept production mail manual, but none of them protect a developer running a live key against a local database full of real family addresses — and a sign-in code is the one message that cannot be dry-run. A relay now rewrites every recipient to one address, preserving the intended recipient in the subject. The accompanying npm run send-test-email refuses to run unless the relay is set, because a casually-run test-send tool that could mail a family eventually will.

Bugs Found and Fixed

SymptomCause
Two household members showed a third member’s profile Both editors seed fields with useState(member.field), which runs once on mount. Selecting another member of the same kind reused the instance and kept its state. Needed a key. The same defect was found and fixed in the new date-time control.
The birthday picker rendered completely unstyled on the public page 37 admin design-token reads with zero fallbacks. Those tokens are scoped to the admin shell, and an undefined variable makes a declaration invalid at computed-value time — the browser drops it rather than falling back.
Three form fields on the roster had no styling at all Class references that resolved to nothing and emitted a literal undefined. A sweep of every admin and public component found exactly these three.
New environment variables never reached the team A blanket .env* ignore was swallowing .env.example, so anything added since it was written was documented only on the machine that added it.
