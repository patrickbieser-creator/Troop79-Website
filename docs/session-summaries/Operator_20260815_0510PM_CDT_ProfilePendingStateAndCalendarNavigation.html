Everything is pushed and the migration is applied to production — but none of it has been used on the live site. That is the single most important thing to carry into the next session. Nine commits and a schema change went out today, verified by tests, by measurement in a browser against a copy of production, and at the data level on production itself. Not verified: a real family walking through it.

What was accomplished

A /profile form is now the record of what is pending

Submitting a demographic update used to make the family's own edit disappear. The form seeded every field from the live record, so it snapped back the moment the change was queued — the proposal survived only as a banner naming which fields had changed, never what they had changed to. A parent could not proofread what they had sent, could not copy a corrected address from one household member into the next, and lost it from view entirely on switching member.

A field now has three values rather than two: what the record says, what is queued, and what is in the input. Measuring against the queued value is what makes the rest fall out of one rule — the submit button disables itself when there is nothing new to send, “discard edits” returns to what was submitted, and editing every field back to the record's own values withdraws the request rather than reporting “nothing changed” while a stale proposal sits invisibly in the queue. Each pending field shows the live value underneath, because once the form displays the proposal, the value a leader is still looking at is visible nowhere else.

A test stack for the bugs that data cannot show you

Every test in this project ran against a real local Postgres, which meant a whole class of bug was structurally uncatchable: last week's member-switcher fault had perfectly correct data behind it and was purely a rendering fault. A second Vitest project renders components in a simulated browser.

It paid for itself the same hour. Two real defects surfaced immediately — an “awaiting review” marker that had been folding itself into every field's spoken name (so a screen reader announced the field as “Phone awaiting review record still says 414-555-0101”), and the one date field that was dropping its description entirely.

A table held back since July finally dropped — after its own safety check turned out to have expired

Parents used to be stored twice: once as a person, and once as a row attached to each child, so a parent of two scouts existed twice with no link between the copies. The retirement was prepared on July 25th and deliberately held.

The reason it was held had quietly stopped being true. July's note recorded that each parent's “Mom” or “Dad” wording was safely duplicated elsewhere. Re-checked against production before dropping anything: that other field holds raw imported text (“Mom Melissa Kingston / Dad Kevin”, “Maya & Anjali”, and three blanks), while the clean word families actually see lived only in the table about to be deleted. 11 of 36 rows would have lost it. The words were given a proper home and migrated first — 36 of 36 preserved and checked against the right people — and only then did the table drop.

The two other worries from July were false alarms, which is worth recording as clearly as the real one: the “missing” phone numbers were the same numbers formatted better on the surviving record, and every “missing” email address was already stored on the person.

The calendar became something you can navigate

Only events with a signup carried a link, and only on their title — so a meeting agenda, which lost its dedicated page in an earlier merge, could not be opened, shared, or bookmarked at all. Every entry now has its own address, reachable from the list and from the month grid, and leaving one returns you to the exact view you left: the right month, the right filter, not the top of the list.

Signing up moved to its own page. Reading about an event and committing to it are different decisions, and putting a form under every description made the description feel like paperwork. The event page now states who is already signed up, by name, before you open anything.

The month grid stopped being crooked

Reported as “a mess.” Measured, it was two separate faults wearing one costume: a long event name was stretching its own day box wider and squeezing the other six, throwing two of six weeks out of alignment with the day headings; and any week containing a campout stood taller than the weeks around it. Both fixed, and the pop-up panel that used to open on today's date without being asked is gone entirely — the chips lead somewhere better now.

What the QA pass caught that nothing else would have

The table drop was followed by a deliberate sweep for things the type checker cannot see. It found four:

  • A database view counting the dropped table's rows — found only because the drop was written without CASCADE, so it refused rather than silently taking the view with it.
  • A one-shot import script that existed to populate the table, already marked “do not re-run,” which would now crash. Removed.
  • Two columns that look like the legacy half of a pair — but the data says the opposite: all 34 rows carry the old-looking ones and zero carry the modern-looking ones. Dropping the wrong pair would have blanked the roster's “entered by” column.
  • A test that borrowed whatever leader record happened to exist, so it passed only on a machine with troop data loaded and failed on any empty one.
