What Was Accomplished

Weekly Advancement Report — noise reduction and data quality

The report's "don't show individual requirements for something already earned" rule only checked awards within the same reporting period — missed a leader backfilling an old requirement long after the rank or badge was actually earned. Fixed by checking the scout's real standing instead: current rank (trigger-maintained, verified reliable before trusting it) plus an all-time merit badge history, not just this week's rows.

Also found and fixed a missing-header bug between consecutive rank/badge requirement groups in the category view — a CommonMark quirk where a heading with no blank line before it silently merges into the previous list instead of rendering as its own line.

Data quality, investigated then fixed: ~75% of the active ledger (7,164 of 9,565 rows) carries a synthetic migration timestamp instead of a real recording time — confirmed via a round-hour signature no organic usage produces. Excluded from the report query immediately; then, after an Opus risk assessment flagged a real (since-resolved) risk to the duplicate-records audit tool, backfilled those rows' recorded time to their actual earned date via a reversible, self-validating migration.

Recent Logins — a new Leader Dashboard section

Investigated before building: admin and family logins are already one event stream since the identity system's unification, not two sources to merge. But the two sign-in methods had incompatible history — email/code links kept a real per-event trail, passkeys only ever remembered the single most recent login. Built a new unified table both methods write to, with device/browser detection, a first-login flag, and a role snapshot at the moment of login. Landed on the real Leader Dashboard (found the bare /admin route was just a redirect stub) with a "view all" page and a separate failed-attempts view.

qa-lead caught one real gap before shipping: the error-swallowing safety net around the new logging only covered part of the code path, so a rare failure there could in theory have broken an otherwise-successful sign-in. Fixed before merge.

Court of Honor — a new ceremony report

Completed ranks, merit badges, and special awards for a date range, by type and by scout, with CSV export — reusing the Weekly Report's engine directly rather than duplicating it. Deliberately filters by the date something was earned, not entered — the opposite rule from the Weekly Report, since a ceremony recognizes what actually happened in the period.

Caught and corrected mid-build: the first version auto-marked every item as "presented" the moment a report was published. Flagged that Court of Honor ceremonies happen outdoors and get rained out — publishing and confirming the ceremony happened are now two separate, explicit actions, and the presentation date is never assumed.

Along the way: corrected a stale backlog claim that two ledger columns were dead code (they're not — verified live, just not yet exercised), and deleted two ledger history rows confirmed to be fictitious placeholder data, not real ceremonies.
