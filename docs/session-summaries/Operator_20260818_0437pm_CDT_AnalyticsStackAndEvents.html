What Was Accomplished

GA4, then GTM, cut over cleanly

Google Analytics 4 shipped first via @next/third-parties/google’s GoogleAnalytics component — verified live not by assumption but by capturing a real POST /g/collect → 204 network request from the browser. Google Tag Manager was added the same session; the root layout now renders GTM or direct GA4, never both, by construction — ruling out double-counted pageviews entirely rather than just avoiding the mistake.

Verification discipline: every claim in this session was checked against a real signal — a live network capture, a published GTM version, or a rendered page — not just "the code looks right."

7 custom events, 1 trigger, 1 tag

Signup funnel (view/start/complete), library resource clicks, proof submissions, outbound BSA links, and .ics subscribe clicks now all flow through GTM as real named GA4 events. Rather than building 7 separate trigger/tag pairs, one regex-matched Custom Event trigger and one GA4 Event tag with a dynamic {{Event}} name cover all of them — extensible to future events without new GTM objects. A new src/lib/analytics.ts helper no-ops safely when GTM isn’t loaded, and params are type-constrained to prevent any PII from being spread into an event by accident.

Site Analytics admin page

New /admin/advancement/dashboard/analytics embeds a Looker Studio report — the only Google-sanctioned way to embed GA4 data, since Google disallows iframing the Reports UI itself. Getting there surfaced three real bugs baked into Google’s own auto-generated report template (see Blockers Resolved below).

Decisions

[D-131] GA4 + GTM analytics stack, mutually exclusive by design

Root layout renders GTM or direct GA4, never both — eliminates double-counting risk structurally rather than by convention.

[D-132] Custom events via one generic trigger + dynamic-name tag

One Custom Event trigger (regex-matched) and one GA4 Event tag with Event Name = {{Event}} cover all 7 current events and any future ones, instead of a tag-per-event pattern.

[D-133] Site Analytics embeds Looker Studio, not a native GA4-API card

Chose the lower-effort, Google-sanctioned embedding path over building a new GA4 Data API integration — proportionate to a project this size. Sharing set to Public per Patrick’s explicit choice; report contains only aggregate traffic data, no scout PII.
