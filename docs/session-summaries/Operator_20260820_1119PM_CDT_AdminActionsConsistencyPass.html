What Was Accomplished

One Actions ▾ pattern, everywhere

The Financial Ledger's Actions dropdown (a single "Actions…" select instead of a wall of buttons, D-156) is now the standard across the admin. Nine screens converted: Calendar (Import CSV), Roll Call & Agendas (Attendance Report), Scoutbook Export (Download / Mark Submitted), Roster (Print), Advancement Report and Court of Honor (Publish, Download CSV), Meeting Plan (Publish to Site), and the Activity Report (Rename or merge an activity — previously an always-open panel, now a modal). Finance's own dropdown was trimmed too — Activity Report and Reimbursements dropped since both duplicate the main nav.

What deliberately stayed out of Actions ▾: per-row/bulk-selection controls (Edit, Void, Delete, Finance's bulk Kind-reassign bar), and workflow-sequential buttons that sit next to a field or warning they depend on (Generate/Regenerate, Save note, Mark Presented on the Report/Court of Honor/Meeting Plan screens). Only the field-free, standalone steps folded in.

Add is never buried behind a menu

News and Calendar both got a direct, always-visible green Add button ("+ Add News", "+ Add Event") — same treatment, same size, as Photo Albums' own "+ Add Album." Any button that only navigated somewhere already reachable from the sidebar (Dashboard's "View Ledger"/"Lookups", Roll Call & Agendas' "Calendar →") was removed rather than kept as a dropdown option.

Corrected mid-session: the Add buttons initially landed at the far left of the tab strip. Patrick flagged it — Add buttons belong at the far right, matching Photo Albums' own placement. Fixed same session, re-verified live, re-ran the full quality gate.

Matching tab-count badges

The pill-shaped count badges from Calendar's Upcoming/Past and News's Current/Archived tabs now appear on Roster's Active Scouts/Inactive/Leaders/Adults strip and Roster Import's Import Queue/Duplicate People strip — both switched from plain parenthesized numbers to the same styled badge. Library's tab badges were deliberately left alone: library.module.css is shared with public-facing pages, so restyling those class definitions would have bled into the public site.

Calendar's CSV import, verified without risking a hung browser

The Import CSV trigger moved from its own visible button into the Actions ▾ select; its hidden file input is now opened via a forwardRef/useImperativeHandle handle instead. Rather than let a real native file-chooser dialog open during verification (which could have hung the browser automation session with no safe way to dismiss it), the file input's click() was patched to record its invocation instead of opening the OS dialog. Driving the dropdown with genuine keyboard input (native <select> type-ahead) confirmed navigator.userActivation.isActive === true at the exact moment the click fired — Chrome's own signal that a real file picker would have opened. Wiring confirmed correct, real dialog never risked.
