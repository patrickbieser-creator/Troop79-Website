What shipped

The site can be found — v1.74.0
/robots.txt and /sitemap.xml were both 404 and the site carried zero structured data. Now: a sitemap generated from live content (372 URLs), an editable robots.txt, Organization / Event / Article / Breadcrumb JSON-LD, and OG cards so a shared link previews. A sitemap is an active invitation to index, so individual scout pages stay out of it unless a leader opts in.
Merit badges live in one place — v1.78.0
The tracker folded into /library/mb/[mbId] and /merit-badges retired. The catalog keeps at-a-glance progress through a Resources / Progress toggle rather than the old three-number-per-tile grid — across 69 badges, “in progress” is zero on 56 of them. Admin deliberately unchanged.
A family roster worth printing — v1.75.0
“Print Roster” used to print whichever admin tab was open. Now a real document, organised by household, with Who-to-call and Patrol pages. No PDF library — the browser already has one. Medical content, BSA IDs and birthdates are permanently absent.
Photo library, four ways — v1.77.0 / v1.79.0
Prints, Timeline, List and Almanac over one filtered set, from six prototyped concepts. The Timeline is the only view that shows the troop’s gaps — there are no albums at all for 2023 or 2024, which year headings hide completely.

Three bugs that reported success

Renaming a published post moved its URL
updateArticle regenerated the slug from the title on every save. Any link already shared started 404ing, and nothing in the editor ever mentioned slugs. Slugs now freeze at publish.
A clone could lose a whole layer and still say it worked
The deep clone read its child rows as const { data: rows } = await …, dropping the error — one transient failure and the jobs vanished with no message. This is the exact defect class lib/db.ts was written to kill after the 2026-08-16 outage, and the clone was ignoring it.
The catalog and the badge page disagreed
Archery read 12 on the grid and 6 one click away — both right, counting different nouns (every award ever vs. scouts currently in the troop). Pre-existing; putting the numbers one click apart is what exposed it.

Worth knowing

  • The local dev database is now a production snapshot (Patrick’s request; the documented recovery path, never db reset). It is what let the clone report be diagnosed against the real event rather than by argument.
  • Four finance tests went red and were right to. They hardcoded kind: 'income' — but that lookup is one a treasurer may edit, and production has deleted it. They now read a kind from the table.
  • The styleguide was lying. It said admin panels are white; D-179 had since split form surfaces from display cards. Two screens were still white-on-white, and anyone reading the guide would have concluded they were the correct ones.
  • Only next build caught one break. Importing a helper into a client component dragged the Supabase server client into the client bundle. Lint, typecheck and 967 tests all passed — the four-part gate earned its keep.
