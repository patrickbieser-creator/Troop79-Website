How it went

Read the sheet, not a description of it
All 24 tabs of Troop 79 Event Registration History and Roster.xlsx were parsed — values and formulas — and mapped against the live schema. Most columns already had a home (sign-ups, participant class, people spine, roll call, finance). Four things did not: car assignment, per-event groups, many-payments money, and leader-only columns. Twelve questions, Patrick answered every one; the plan was reviewed by tech-lead and qa-lead the same day (both go-with-changes, all folded in); Patrick signed off the two safeguarding items. Then /goal build phases 0-4.

What shipped

Phase 0 — schema, additive first
Seats counted including the driver with the legacy column kept in step by trigger; ride status per leg; group sets / groups / members with trigger-owned cars and a place_in_group RPC that locks the group row; a derived balance view, per-person owed override, milestones, ledger rows that know their calendar entry; leader-only questions (the family RPC skips them). 40 schema tests, failing first.
v1.81.0 — who rides with whom
The family form asks “seats in your vehicle, including you” (prefilled from the driver’s remembered capacity) and a ride status per leg. The roster gains Ride and Rides there/back tiles (the sheet’s Need/Avail/Short-Over). Rides & assignments: a card per car, a Needs-a-ride pool, drag or Move…. Families see their own rides on the event page — “riding with the Porters (there)”.
v1.82.0 — patrols, tents, crews, teams
The builder’s Assignments block (presets by category, add any set); patrols seed from the roster and place late sign-ups automatically, never writing back; families can pick a tent; the roster shows Groups. The jobs/slots question was answered: reuse the picker UI, not the table.
v1.83.0 — the money block
Many payments per person (the one-payment index dropped in the same deploy as the rewritten actions), refunds as negative rows, overpayments credited to the scout account, payment_received retired in favour of the derived view. A Money tab per event: owed/paid/balance, record/refund/credit, expenses (troop paid, or a leader fronted it → reimbursement request), income by method, P&L, deposit schedules with a Behind badge and an editable reminder email.
v1.84.0 — leader columns and the snapshot
“Health form in hand” / “Registered with council” as leader-only roster cells (free text prints only when the leader says so); and /admin/snapshot/[id] — the whole tab on paper: roster by patrol, car manifests with blank lines for open seats, contacts, money, schedule. Outside the admin shell because the page is the document.

Deployed — in the right order

Code first, then the database
On “Push now”: git push, Vercel’s commit status polled to success, only then supabase db push (six migrations; dry-run now “up to date”). Production eyes-on: roster, assignments, money and snapshot all render on www.troop-79.com. At Patrick’s instruction the old free-text “Can you help drive?” question was removed from Fall Campout — the Drivers block owns that now.
