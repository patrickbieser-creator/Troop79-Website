How it went

Practice data, then a live click-through
Built an event-sheet importer and a production→local refresh script so the whole logistics feature set could be exercised against a realistic practice event (Pinewoods Campout) without touching production. Patrick then worked through the roster, money, assignments and snapshot screens turn by turn, calling out exactly what didn’t work — a weaving column here, a tab that made no sense there — and each was fixed and gated (lint/typecheck/test/build) before moving to the next.

What shipped

The roster grid, rebuilt around the common case
A new Attending tab shows only people actually coming (status='yes' AND participation='full'); declines, waitlist, driver-only, contributors and removed people moved to a new Other responses tab. Driving and Ride collapsed into four narrow, centered, sortable columns with shorthand — a bare seat count, a driver named once with no title, a blank cell (not “needs”) when unplaced. One column per patrol/tent/crew instead of one crowded list. Class renders as a small colored pill (youth light, adult dark) with a full legend on hover. Feature columns — Jobs, Answers, Driving/Ride, even the row Edit dialog’s Transportation section — now appear only when the event actually uses that feature, the same block-checklist philosophy the Builder already used.
One navigation bar for every event page
Builder, Roster, each assignment set, Money and Snapshot used to carry their own, mutually inconsistent set of text links. A new shared, data-driven EventNav now renders identically on all five — and only shows what the event has: no set tabs on an event with no cars or patrols, no Money tab on an event with no fees. Found and fixed on the Unity Church service project, which had been showing Rides & Assignments and Money tabs for features it doesn’t use.
Snapshot moved into the workspace
The printable snapshot used to render straight to a bare document. It now has a proper workspace page (sidebar, the shared nav, a By-patrol / A–Z / Adults-JLs-Scouts order switch) with printing as one explicit further step, opening the clean print view in a new tab. The printed roster gained Patrol/Tent columns and a bare-number Grade; car cards stopped repeating the driver’s phone, which Contacts already carries.
Money: two real bugs found and fixed while testing
Clicking “Credit to account” more than once minted a duplicate scout-account credit each time — crediting never changed the event’s displayed balance, so the button never went away. Separately, a payment recorded “from” the scout account had been writing a positive row on that account (raising the balance) instead of debiting it. Both are fixed: the balances view now nets credits, and notional accounts (scout account, scholarship fund) store a fee payment as a negative row, a refund as positive. A new Record-payment guard shows the chosen account’s live balance and requires an explicit acknowledgement before letting it go negative, with a one-click offer to use the scholarship fund instead.
