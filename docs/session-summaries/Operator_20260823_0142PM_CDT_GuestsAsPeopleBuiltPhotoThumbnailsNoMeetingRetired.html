How it went

Patrick said “work on guests as people” and the whole plan shipped in a day: schema, RPC, both family forms, the Builder, the leader’s Add a guest, a People → Guests tab, then the Phase 3 tightening the same afternoon on his “proceed.” Two forks ran the admin side and the Guests tab while the orchestrator built the schema/RPC and public forms; a third fork executed the parked photo-thumbnails plan in parallel. qa-lead reviewed the code (go-with-changes, 82/100) and its two missing security tests were added before deploy. Mid-stream Patrick answered the Remove → re-register question (“(a) RPC revives the cancelled row”), sent a duplicate-header bug, then three UX rounds on the guest editor (status copy → member-style rows with an Attending toggle → locked until someone attends) plus “Saving changes… → Done,” a greyed-out Save, and the request that the Save behaviour become a written rule. Last: an evaluation and removal of the “No Meeting” calendar category.

Two things the tests could not see and the browser did: client components importing a value from lib/event-signup dragged the server Supabase client in and blanked the Builder (fixed by splitting lib/guest-mode.ts / lib/guest-payload.ts out); and the photo backfill’s verify step HEADed the Bunny Storage API, which has no HEAD — the safety gate refused to repoint anything, the 29 orphaned uploads were deleted, verify was fixed (1-byte ranged GET + patient CDN check) and the re-run landed 29 covers.

What shipped

Guests as People — Phases 0a–3 (v1.87.0, v1.87.1)

event_signups.guest_mode none / count / named (Builder radiogroup, family prompt, priced-count warning, per-category presets); a named guest is a people row flagged guest_host_household_id — never a household member (DB guard), hidden from the directory and every picker; the RPC takes guest rows in its payload (25/household + 80-char caps, 20/event, re-pick validated against the household, dropped guests → ‘no’); “add again” picks and a typed-name confirm instead of silent merges; adult-only phone; leader Add a guest offers known guests; People → Guests tab (Merge into… / Forget / 12-month nudge); snapshot “+N guests” in count mode. Phase 3: person_id NOT NULL, guest_name/allow_guests/old CHECKs dropped, car-sync function re-created without the column.

Remove → re-register revives the Removed row (v1.87.0)

Patrick’s option (a): the RPC revives the latest cancelled row for a person instead of inserting a twin, so payments, placements, job claims and answers stay attached. qa-lead’s caveat — a family re-submit silently un-removes a deliberate Remove — explained to Patrick; a roster marker is on the backlog.

Photo thumbnails (v1.87.0) + production backfill

Browser resize before upload in every image picker (covers 1200 px, general 1600, JPEG ~q0.82, PNG only with real alpha, byte-identical pass-through for non-images/small files) with a “4.0 MB → 180 KB” line and a quiet per-file “Keep original size” exception; safeImageUrl on /photos; cdn_url spaces fixed (24 rows). Backfill run on production: 29 covers, 60.7 MB → 4.9 MB, originals kept, re-run is a no-op; /photos now serves ~5.1 MB of covers (was 62 MB).

Sign-up form UX (v1.87.1–v1.87.5)

“+ Add another parent or guardian” (was “another adult”); guests as a GUESTS section in the Scouts/Adults style with the Attending / Can’t make it toggle, editable name/class/phone and Remove; the section locked (heading + one-line why) until someone in the household is attending / has a job; “Saving changes…” overlay on submit and a brief “Done” flash on return; Save changes greyed and reading “Saved” until the draft differs; the duplicate “Signing up the … household” bar on job-board pages removed.

The Save-button standard (rule)

Written into next-app/AGENTS.md and Architect PATTERNS: every Save/Submit on an already-saved form is disabled until dirty, labelled “Save changes”/“Saved”, greyed not hidden, with Saving… → Done feedback. An audit pass over every other form is the top backlog item.

“No Meeting” category retired (v1.87.3)

Evaluated and removed on Patrick’s go: a week with no meeting is a Troop Meeting titled “No Troop Meeting” (he was already doing this). Four entries recategorized with titles intact, lookup row deleted, behavior CHECK = (‘meeting’), every no_meeting branch gone; the ICS feed, calendar filters and attendance % are unaffected by construction.
