What shipped

Job-code columns for job-heavy events (item 3)
A rummage sale has 20–30 jobs; the roster’s single prose “Jobs” column was unreadable at that scale. Each job now has a 1–5 character code (signup_slots.code, leader-set in the Builder or derived from the name by lib/job-codes.ts, unique per event) and the roster grid shows one narrow column per job headed by its code: a tick when claimed with the note on hover, a thin day band when jobs span days, a Show/Hide jobs toggle, and click-a-code sorts the claimers to the top. The Builder got a Code field (derived code as the placeholder) and lists jobs as “Setup crew (SC)”; the printed snapshot gained a Jobs section — the readable assignment list. Families never see codes.
Event Logistics step 15 (item 1) and the backfill (item 2)
The legacy “seats besides the driver” columns and their two-way sync are gone (20260823120000); seats have been “including the driver” since v1.81 and that is now the only representation. The Phase 5 historical backfill was removed from the backlog at Patrick’s word; the plan moved to Plans/Completed/.
Signup Builder in tabs
Blocks stays at the top; Settings (default), Price tiers, Jobs, Questions and Assignments are now tabs under it so it is clear where one form ends and the next begins; “Add a job” is tucked away until its right-side button is clicked, like the page’s other add controls.
Job board: three bugs from the Unity Church service project
Save changes did nothing — it re-submitted unchanged data; it is now disabled until something actually differs and reads “Saved” otherwise. A removed name came back — the person was simply left out of the payload, so the RPC never touched their entry and their claim survived; a removed person is now sent as declined and the server deletes the stale claims. A guest “showed up nowhere” — Fred Pike was saved (verified in production), but the form never re-seeded saved guests and the recap ignored them; saved guests now come back into the editor, the recap lists them, and a guest added before anyone has a job is held with a reason (a guest row needs a host).
Delete permanently, with reasons
On the roster’s Other responses tab a Removed row can now be erased from the database (two-click confirm). If ledger rows, guest rows it hosts, or a car it drives still reference it, the delete is refused with each reason and how to clear it — the money FK would refuse anyway; guests and cars would otherwise cascade away silently.
Guests as people — designed and reviewed, not built (item 4)
Plans/Guests-As-People.md: a per-event Guests mode (none / count / named, defaulted by category), named guests as people rows flagged by host household (out of the directory and pickers, a People → Guests tab), guest rows written inside the signup RPC with caps, re-use only by pick-list or explicit confirm, promotion via the existing merge. tech-lead and qa-lead both returned go-with-changes; every change is folded into the plan. Five open questions await Patrick.
