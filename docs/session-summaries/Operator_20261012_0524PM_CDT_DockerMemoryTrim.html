What Was Accomplished

The outcome: Docker can no longer take more than 6 GB, the local Supabase stack runs in about 0.8 GB, and an hourly job hands the Docker VM’s file cache back to Windows.

The survey

Of Pensieve, Pen2, Pen-Vision, OMG, SecondBrain and Troop 79, only Troop 79 uses local Docker Supabase. OMG’s dev already uses its hosted production database; Pen2, Pen-Vision and SecondBrain use SQLite; Pensieve uses a JSON file. Moving Troop 79 dev to hosted would need a third Supabase project (Pro at about $25 a month, or a second free org), so the cheaper fix came first.

The fix

A .wslconfig caps the VM at 6 GB. Analytics, realtime and edge functions are off in the local Supabase config. The Supabase CLI moved to 2.120.0. Patrick saw VmmemWSL at about 5 GB while the containers used 0.7 GB: the rest was Linux file cache (3.4 GB). Dropping it took the VM down to 1.2 GB used, and the hourly “Docker Drop Cache” task now repeats that.
