Notice — two entries in the Heavy scenario demonstrate Decision #4’s date rule. Ines Rocha · First Class 9a was earned Jul 22 (just before this report’s Jul 28 start) but entered today — it lands in this report because every query filters on entered_at, never date, and it shows “earned Jul 22” automatically since that date falls outside the report’s own range. Marcus Whitfield · Camping req 1 is the more extreme case Patrick described — credited today for something completed June 2025, over a year ago — and shows “earned June 2, 2025” the same way, with no toggle needed. Every other line in this report was earned within the dateline, so none of them show a date at all.

Editing — click any bold requirement/badge label to fix a typo (Category view) or a scout name (Category view only). Use Remove to drop a scout from a line at a family’s request — works in either view, since both read/write the same underlying report. Edits only apply to this report’s copy — the underlying catalog and roster are untouched.

New 2026-08-17: same consolidated content, reorganized alphabetically by scout — no separate query, just a different read of the same generated report. Useful on a heavy week when most visitors want to find one kid, not scan five sections.
