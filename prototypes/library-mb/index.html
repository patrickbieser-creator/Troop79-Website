Sign in with your family password to see your scout’s progress on each requirement and to send in proof when one is done.

What this prototype replaces

Today /library/mb/[mbId] renders four stacked sections after the header: Scout Progress grid → Requirements tree → Whole-badge resources (+ one SectionDivider per top-level requirement with resources) → an “I did this” radio picker listing every leaf again. This prototype keeps the header, stats and grid, and folds the other three into one list. Whole-badge resources are the first row of that list (“For the whole badge”, ghost MB tag) — no separate divider.

Row grammar (rev 2, after Patrick’s review)

At rest: code · label · small Done · Jun 12 / Pending pill per own scout · up to three icon-only actions, in this order and with these rules (Patrick, 2026-09-07): 1. View resources (count) — only when the requirement has any; name “View resources — 4a (3)”; it and the requirement text open the row. 2. I did this — only while at least one own scout is not done or pending; hidden (not greyed) once every own scout is; never for visitors. 3. Suggest a resource — always, every viewer. Nothing else. Every icon has a title, an aria-label naming the requirement, and a tooltip bubble on hover/focus. Opened: one quiet line per resource (glyph · ★ title · host in muted text; YouTube = static thumbnail, links out) and the counselor note. Group rows (1, 2, 3, 4, 8): the label toggles the child rows; the View resources icon opens the group’s own resources. Not-yet-done scouts show no pill at all.

Legend: one line at the top of the list naming the three icons with their conditions (the I did this entry drops out for visitors). Grid: the navy header rule runs under the second header row everywhere, so the Scout column’s rule meets Award’s.

Whose progress (Patrick, 2026-09-07): a household with two or more scouts gets the production ScoutSwitcher (library/_components/scout-switcher.tsx, its “Showing progress for” select) directly under the Scout Progress grid and above the Requirements divider. The rows then personalise to that one scout: pill “Done · Apr 19” with no initials, I did this only where that scout still needs it, and the proof dialog pre-selects them (siblings stay pickable, done/pending ones disabled). Default = first scout; the choice is remembered for the session, exactly like ?viewScout= on /library, which is the mechanism to reuse here: this page today drops viewScout (see its header comment) and would start honouring it through resolveLibraryViewer(supabase, viewScout) like the rank page does. A one-scout household gets the switcher’s plain-text mode (“Showing progress for Ari D.”), as production always names whose progress is showing; the scout viewer gets the same line; visitors get nothing. The grid keeps showing every household scout.

Plan: attaching a video / link / doc to ONE requirement

  1. Entry point. The Suggest a resource icon passes target=mb_req:{mbId}-{code}; the submit flow validates the code against merit_badge_requirements, shows it read-only with a go-back link.
  2. Write. Insert library_resources (status=pending, submitted_person_id) and its library_placements row together, so the queue and the submitter’s pending line know the target from the start; public reads already filter on status.
  3. Display. In page.tsx replace the byTopCode/topLevelCodeOf grouping with an exact-code map; delete the per-top-level dividers, the whole-badge card list, and MbProofPicker; the tree component grows the accordion sub-row and the actions.
  4. Submitter’s pending line. One extra query for a signed-in viewer: pending resources on this badge where submitted_person_id = viewer.
  5. Review queue. Show the target as “Chemistry › 4c — Flame tests”; re-target, pin, sort at the placement level (exists).
  6. Notes. Narrative editor gains a requirement picker for mb_req targets.
  7. Rank page. Same row grammar with rank_req + {rankId}-{code}. Not built here.

Interaction spec

  • Accordion: button + hidden with aria-expanded/aria-controls, never <details> (D-070). Label button and Resources icon both control the same sub-row. Expand all / Collapse all drive both the group children and every sub-row.
  • Chevron 180 ms ease; dialog 150 ms ease-out; new pending line 180 ms rise.
  • Icons are inline SVG in navy, 28 px min hit area, tooltip bubble below the button on hover/focus-visible (never inline, so the row never reflows — verified at 375 px).
  • Dialogs are native showModal(); success announced through a polite live region.

What is mocked

  • All data in-page; invented scouts, household, counselor, resources, dates. Requirement text is BSA’s (paraphrased).
  • YouTube thumbnails are inline SVG placeholders. Uploads are never read. “Reset demo data” restores the seed.
