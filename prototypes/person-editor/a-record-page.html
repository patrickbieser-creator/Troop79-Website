Concept

A read-only record page is the default. Every section shows its saved values and exactly one Edit. Edit turns that section — and only that section — into a form with a dirty-gated Save changes and a Cancel. Anything that commits on click (email addresses, parents/guardians, roles) lives in a dashed "Takes effect immediately" block, never inside a draft form. Status is a read row whose Edit asks for a reason and then confirms. This is Jenna's Direction 1.

What it fixes (Jenna's numbering)

  • #1 One save model per section; the immediate blocks are visually and verbally labelled. There is never a grey "Saved" button under something that already saved.
  • #2 Status is built the same way for scouts and adults: read row → Edit → reason → confirm.
  • #3 Parents/guardians on a scout are an immediate block outside any form, so Cancel never promises what it cannot do.
  • #4 Merge and Delete both open the same confirm dialog naming consequences; Delete is refused (button disabled with the reason) while anything is attached.
  • #5 Household is a draft field; the Save toast reads "Household: A → B" with an 8-second Undo.
  • #6 End role confirms and names the tab move; Grant role commits but announces the move in a notice.
  • #7 No standing hint paragraphs. Each section has at most one "How this works" disclosure; gates and consequences are said at the moment of the action (dialog copy, disabled-reason titles).

States and transitions

  • Section: read → (Edit) → editing (Save disabled, "No changes yet") → dirty (Save enabled, "Save changes") → saving (600 ms mocked, button "Saving…", all inputs disabled) → done (button "Done" 1.2 s, card flashes green 1.4 s) → read with "Saved just now" stamp.
  • Blocked save: required first/last name empty → Save disabled with title "First and last name are required", inline error under the field.
  • Opening Edit on a second section while one is dirty → confirm "Discard unsaved changes in X?".
  • Back to roster while dirty → same confirm.
  • Status: read → Edit → reason input (adult: free text; scout: required select) → "Mark inactive" opens confirm dialog → saving → read with new pill; reactivate is one confirm.
  • Pending update banner: sits inside the section whose fields it touches; Approve applies only that section's rows (see deviation); Reject asks for an optional reason.
  • Send sign-in link: sent (masked address, 15 min) / rate-limited (second click inside 5 min) / unreachable (no deliverable address → button disabled with reason, hint links to Contact).
  • Toast: 5 s, 8 s when it carries Undo; dismissible; role=status.

Timings and motion

  • Server round-trip mocked at 600 ms. Card flash 1.4 s ease. Button hover/background 150 ms (--admin-transition). No other animation; reduced-motion users lose nothing.

Responsive

  • Two columns (main + 280 px sidebar) above 760 px; single column below. Definition lists and form grids collapse to one column. Inputs go to 16 px below 760 px (iOS no-zoom floor). Roster hides Phone / Roles / Household columns on narrow screens. No horizontal scroll at 375 px.

Accessibility

  • Native <dialog> for confirms (focus trap, Esc, backdrop). Visible focus rings on every control. Section cards are landmarks (section + h2). Status pill text is never colour-only. Immediate blocks carry a text label, not just a dashed border. Disabled buttons keep a title explaining why.

What is mocked

  • All server actions (600 ms delay, always succeed). Search is over the six sample people. Rate limit is a 5-minute in-memory stamp. Merge marks the loser as merged and jumps to the survivor. Nothing persists on reload.

Deviations from the brief / open questions

  • Pending updates are approved per section, not per request. Today a change request is one unit (approve all or nothing). Splitting it across sections is the natural consequence of Jenna's "banner inside the section it touches"; it needs a per-field approve on the server or a rule that the first section's Approve applies the lot. Flagged for Patrick.
  • This is a page, not a modal — the roster is behind a Back link. The current editor is a dialog; every reference product uses a page, and the sidebar needs the width.
  • Scout and adult share one shell; only the section list differs. "Things we should know" was folded into Details as a full-width field rather than kept as its own section.
  • Adult inactive reason stays free text; scout stays the fixed list — unifying them is Patrick's call.
