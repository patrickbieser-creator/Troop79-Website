Concept

The record is a property panel (Linear / Notion / HubSpot "About this contact"). Every property is a single click-to-edit control that commits on its own: click the value, change it, press Enter or the check — it saves, the row shows a green "Saved" tick, and a toast offers Undo for 8 seconds. There is no Save button anywhere on the page. Status is a property whose popover asks for the reason before it commits. Lists that already commit on click (emails, family, roles) sit in the right column with the same dashed "Takes effect immediately" treatment as A, so the whole page has exactly one save model: immediately.

What it fixes (Jenna's numbering)

  • #1, #2, #3 — dissolved rather than fixed: there is one model everywhere, for scouts and adults, and nothing can be "half saved" because nothing waits.
  • #4 Merge and Delete keep a real confirm dialog; they are the only dialogs on the page, which makes them feel as heavy as they are.
  • #5 Household is a property; committing it toasts "Household: A → B · Undo" and lands in Recent changes with its own Undo.
  • #6 End role confirms with the tab-move consequence; Grant role commits and announces the move.
  • #7 No hint paragraphs; each group has a "How this works" disclosure; consequences are said in the status popover and the dialogs.

Accidental-edit guard (the risk of this direction)

  • Values are buttons with a hover/focus pencil — a click opens the editor, it never types straight into the value.
  • Nothing commits on blur. Only Enter or the check commits; Esc or the cross reverts. Clicking elsewhere leaves the editor open.
  • Every commit gets an 8-second Undo toast with a visible countdown bar, and is written to Recent changes in the sidebar with a per-entry Undo that survives the toast.
  • Required fields (first/last name) refuse an empty commit inline.
  • Consequential properties (Status, Household) use a popover with an explicit Apply instead of a bare input.

States and transitions

  • Property: read → click → editing (input focused, text selected) → Enter/check → saving (600 ms, "Saving…") → saved (tick 2 s) → read. Esc/cross → read with no change. Undo → saving → read with the old value.
  • Status popover: Active/Inactive radios; Inactive reveals the reason (adult free text, scout required select); Apply commits; undo restores the previous status and reason.
  • Pending update: a summary banner at the top ("3 proposed changes from Marcus Whitlock" with Approve all / Reject all) plus a yellow row under each affected property with the proposed value and per-field Approve / Reject.
  • Send sign-in link, emails, family, roles, merge, delete, promote: same as Direction A.

Timings

  • Round-trip mocked at 600 ms. Saved tick 2 s. Undo window 8 s with a linear countdown bar. Hover pencil 150 ms.

Responsive

  • Two columns (properties + 340 px lists) above 760 px; stacked below. Property rows go label-over-value. Pencils are always visible on touch widths since there is no hover. Inputs 16 px on small screens. No horizontal scroll at 375 px.

Accessibility

  • Each value is a real button labelled "Edit {property}"; the editor is a labelled input with Enter/Esc documented in a visible key hint. Saved/Saving announced via the toast's role=status. Focus returns to the value button after commit or cancel.

What is mocked

  • All server actions (600 ms, always succeed). The Recent changes log is session-only. No conflict handling if two leaders edit at once — a real build needs it more here than in A, since edits are many and small.

Deviations / open questions

  • Fourteen tiny saves instead of one is a real trade-off for a post-recharter clean-up. If leaders bulk-edit, A or C fits better.
  • Pending updates are approved per field here (natural for this model) — needs per-field approval on the server or a rule that "Approve all" is the only real option.
  • The house Save standard (labelled state, Saving → Done) has no home in this direction because there is no Save. The standard would need an amendment blessing the tick + undo toast as the equivalent.
