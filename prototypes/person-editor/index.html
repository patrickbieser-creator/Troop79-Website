Person editor — three directions

The adult, leader and scout editors today mix three save models on one screen (immediate, dirty-gated, and approve), which is how a status change looked like it never saved. Each direction below is a working prototype of the same six invented people (an adult with a pending family update, an inactive adult, a leader with two roles, a scout with two parents, a scout with a pending update, a clean duplicate). Every one opens from a mock roster, works at 375 px, and ends with a hidden "Handoff notes" disclosure. Jenna's audit and the direction definitions are in Plans/Person-Editor-Rethink.md.

ARecord page + scoped section edit Jenna's recommendation

A read-only record page is the default; each section (Status, Details, Contact & sign-in, Household & family, Roles) has one Edit that turns only that section into a form with Save/Cancel. Anything that commits on click lives in a dashed "Takes effect immediately" block, never inside a form. Stripe-style.

Fixes #1 #2 #3 #4 #5 #6 #7 — one save model per section; status is read → Edit → reason → confirm for scouts and adults alike; parents/guardians are outside any form; merge confirms; household saves say "A → B" with Undo; end-role confirms.

Build cost: medium Reuses FormPanel, SaveButton, DiscardButton, Dialog. New: read-mode renderers, page route (or a wider dialog), per-section pending banners.

Open Direction A

BProperty panel, click-to-edit

Every property is a single click-to-edit control that saves on Enter and shows a green tick; there is no Save button anywhere. Status is a property whose popover asks for the reason before it commits. An 8-second Undo toast and a "Recent changes" log with per-entry Undo are the guard against accidental edits. Linear / Notion / HubSpot-About style.

Dissolves #1 #2 #3 (one model: immediately); fixes #4 #5 #6 #7. Risk: fourteen small saves in a bulk clean-up; the house Save standard has nothing to attach to.

Build cost: medium–high One per-field server action plus an undo path for each; change log table for Recent changes; conflict handling matters more.

Open Direction B

CTabs + one sticky save bar

Persistent header, tabs (Overview / Details / Contact & sign-in / Household & family / Roles / History) and an always-editable form. Any draft edit anywhere lights one sticky footer — "Save 3 changes · Discard" — with a dot on each tab that holds edits. Status and household are draft fields. History is a real change log. Salesforce / Google Contacts style, with Jenna's Direction 3 log.

Fixes #1 #2 #3 #4 #5 #6 #7 — one Save, always in the same place, following the house standard to the letter; immediate lists say "not part of the save bar".

Build cost: high One atomic "save person" action across people + scouts + household_members; a change-log table; new tabbed IA. Most durable as the roster grows.

  4. Open Marcus Whitlock, grant Adult leader — the notice says he now appears under Leaders. Open Priya Raman (Leaders) and end a role; the confirm names the tab move.

  6. Open a scout (Theo Whitlock): parents are an immediate list; Nikhil Raman has a pending update; the scout inactive reason is a required list.

  8. Narrow the window to 375 px and repeat step 1.
